# Skeletal animation implementation status

Source plan: [skeletal_animation_pipeline.md](skeletal_animation_pipeline.md).

## Milestone 1: foundation — delivered

- Started the standalone CPU evaluator in `graaal/SkeletalAnimation.py`: immutable copied skeleton and uniformly sampled clip arrays; validated depth-first preorder; xyzw float32 local transforms; normalized, sign-continuous rotations; batched clip sampling and depth-batched local-to-model transforms; row-major 3x4 skin matrices.
- Clips include both endpoints at `(frame_count - 1) / fps`; loop playback wraps at that duration, so authored seamless loops must match at the endpoints. Sampling uses normalized linear quaternion interpolation and supports negative times, clamping, and single-frame clips.
- Added focused CPU regression coverage for hierarchy validation, interpolation, looping, resource ownership, and transforms.
- Added optional `EcsAnimationAdapter`, `SkeletonRef`, and `ClipPlayer`: playback supports looping, reverse speed, seeking, pausing, and clamping. The adapter groups by skeleton and clip, emits full entity handles with batched matrices, and refetches selections on each update; it can run as a fixed-step scheduler callback.
- `SkeletalAnimation.skin_vertices` provides CPU mesh deformation with inverse-transpose normals. `MaterialRenderer.update_mesh_vertices` updates raster and deferred vertices together, so ordinary material shaders and transparency work with animated geometry. Each independently animated pose currently needs its own registered mesh and conservative bounds; vertex uploads scale with mesh size.
- `MaterialSkinningAdapter` maps full owner IDs and pose batches to separate registered material meshes, retains bind-pose vertices and supports explicit unbinding on entity removal. It preflights each batch before uploading, leaving ECS ownership and draw setup to the application.
- `SkeletalGltf.load_skinned_gltf` imports a supported subset of skinned glTF independently of ECS or rendering. It reorders arbitrary joint lists into depth-first order, remaps weights and inverse binds, and resamples LINEAR joint tracks at uniform rate. Unsupported hierarchy transforms, animation modes and morph targets are rejected; the API guide records the limits.
- `SkinMatrixBuffer` supplies one fixed-capacity GPU storage buffer with contiguous per-owner allocations, full-handle keys and validated pose uploads. The reusable `skinning.shaderlib` applies weighted skin matrices and inverse-transpose normals.
- `MaterialRenderer(skin_palette=...)` skins shared meshes per owner on the GPU before material vertex hooks, in raster and deferred transparent shading. It validates influence data and allocated ranges, refreshes palette addresses after regrouping, and supports static meshes alongside skinned meshes. The application owns palette allocation, upload and lifetime ordering.
- `scenes/simple_animation_example.py` uses the reusable glTF loader for Greenman, advances three ECS players, and renders a shared GPU-skinned mesh using `EcsMaterialAdapter`.
- Validation: 51 focused animation and material tests pass, including transparent rendering after a vertex update; the updated Greenman scene passed a three-frame GPU smoke test.
- Validation of ECS playback and the existing ECS subsystems: 152 tests passed. The ECS-driven example also passed a three-frame GPU smoke test.
- Multi-character mapping validation: 15 focused tests passed, including indexed material meshes and full-handle reuse; the three-character scene passed a three-frame GPU smoke test.
- Importer validation: 18 focused animation, material and importer tests passed, including reordered joints, inverse binds, quaternion resampling and unsupported-input rejection. The scene passed a three-frame GPU smoke test using the reusable importer.
- GPU foundation validation: 21 focused tests passed, including GPU-versus-NumPy weighted skinning with reflected scale, range recycling, batched uploads and error preflight.
- GPU material validation: 71 focused tests passed, including shared meshes, opaque and transparent GPU-versus-CPU shading at 1x and 4x MSAA, palette relocation and entity recycling; eight GPU material tests passed after adding mixed static/skinned coverage. Ten existing transparency and render-composition tests also passed. The updated Greenman scene passed a three-frame GPU smoke test.
- `PosePalette` reconciles complete pose snapshots with palette allocations, reclaims absent owners, initializes new allocations and uploads batches. The Greenman scene uses it before material synchronization. The caller still coordinates draw membership and prior GPU work; failed allocations roll back newly acquired ranges after releasing absent owners.
- Palette lifecycle validation: four CPU tests passed using the real allocation logic with a fake GPU buffer, covering full-handle recycling, uploads, invalid batches, capacity failure and external release. The interactive GPU scene was not run in this validation.
- Added optional output arrays for clip sampling, model transforms and skin matrices. The ECS adapter retains growable pose and matrix buffers by skeleton and source clip and can explicitly discard its cache. Returned matrix views must be consumed or copied before the next update, including a failed update; interpolation and crossfades still allocate intermediates.
- Pose-buffer validation: three standard-library tests passed for reused output arrays, validation, buffer reuse, growth, shrinking and explicit cache clearing. Broader asset format coverage and further allocation optimization remain follow-up work as needed.

## Milestone 2: transitions and root motion — started

- `ClipPlayer` now supports two-clip transitions with separate target time, speed and loop settings. The ECS adapter advances and blends active transitions in batches, pauses them with playback, and promotes the target on completion; invalid transitions fail before player state changes. The same pose batches feed the existing GPU material palette.
- The ECS adapter exposes per-skeleton `sample_batches`: full owner handles, two clip IDs, normalized times and weights per player, and an in-place-root flag. The samples capture completed fades before promotion.

- Added ECS-independent `sample_clip_pairs` to evaluate controller sample arrays, batching by clip pair while preserving instance order. Times clamp because controllers already handle wrapping; root-motion removal remains explicit.
- Split controller advancement from CPU pose evaluation: `update(..., evaluate_poses=False)` emits samples, events and root requests, while `evaluate_samples` produces poses later using reusable output buffers. Scheduler callbacks `advance` and `finalize` allow gameplay or physics work between the two phases; the existing `evaluate` callback and default update retain combined behavior.

- Added standalone batched rigid root-motion extraction. It returns requested transforms in the starting root frame, composes complete cycles for looping and reverse playback, and keeps movement and physics decisions with the caller. `in_place` anchors the sampled root at the skeleton reference, and `character_delta` converts requests to that character frame so the resulting pose can use existing skinning.
- ECS players can opt in to root-motion extraction. The adapter emits character-frame requests keyed by full entity handles and supplies in-place skin matrices to the existing material path. The application owns movement and physics acceptance.
- Root-motion crossfades blend source and target movement deltas at the midpoint fade weight, then compose any target-only remainder when the fade ends within a tick. Translation blends linearly and rotation uses shortest-path normalized quaternion interpolation. This is an explicitly documented fixed-step approximation; each clip needs a compatible root-motion resource.

An ECS movement system clamps requested displacement to a boundary, records accepted displacement separately, and finalizes the in-place pose afterward. Greenman's move clip has no authored horizontal root movement, so the example uses a synthetic rig; rendered locomotion and physics integration remain future work.
- Added a rendered Greenman locomotion scene with synthetic root translation, ECS crossfades, a fixed-step movement boundary, requested/accepted displacement controls and GPU material skinning. Its boundary is illustrative; physics and reconciliation remain future work. Validation: a three-frame windowed GPU smoke test and 13 focused animation tests passed; generated walk and run clips produced 1.25 and 2.5 units of X displacement per cycle.
